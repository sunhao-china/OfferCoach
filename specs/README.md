# specs 状态流转规范 v1.0

> 建立时间：2026-10-21。SDD 规格文件按**状态文件夹**存放：**移动文件 = 变更状态**，文件名不携带状态。

## 状态机

```
01-planned ──开工──► 02-in-progress ──完成(AC 全绿 + DoD)──► 03-implemented
     │                                                         │
     └────────────── 废弃 / 被新版本替代 ───────────► 04-archived ◄┘
```

| 文件夹 | 状态 | 进入条件 | 离开条件 |
|---|---|---|---|
| `01-planned` | 已计划（最初始状态） | 新步骤开工前，详细计划落盘 | 开始写代码 |
| `02-in-progress` | 开发中 | 开始写代码 | AC 全部有测试且通过、ruff/mypy 干净、DoD 勾选 |
| `03-implemented` | 已实现 | 上述完成 | 被新版本替代或废弃 |
| `04-archived` | 归档 | 规格废弃或被替代 | — |

## 规则

1. **每一步先落计划**：新模块开工前，详细计划必须写入 `01-planned/{模块}/{名称}.md`，才允许动代码
2. **流转 = 移动文件**：状态变化时把 spec 文件移到对应状态文件夹，目录结构 `{状态}/{模块}/{名称}.md`
3. **spec 是唯一事实来源**：代码与 spec 不一致时，改 spec（重新流转）或改代码，不允许静默漂移
4. **引用同步**：文档/代码引用 spec 路径时用相对路径，移动后同步更新引用
5. **计划内容固定为五节**：目标 / 输入输出契约 / 验收标准（AC，每条 → 至少一个测试）/ 实施计划（文件清单 + 测试映射）/ Definition of Done
